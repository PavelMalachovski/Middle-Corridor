# mc-status — Middle Corridor Status

Оперативная сводка по **Среднему коридору (TITR)** — Китай → Казахстан → Каспий →
Кавказ → Чёрное море → Европа — в Telegram: публичный канал с алертами и бот
с интерактивом.

Плюс **веб-карта** (фаза 2, прототип на мок-данных): грузы, паромы, погода
и новости на одной карте — см. [Веб-карта](#веб-карта-фаза-2-прототип).

Продукт закрывает три боли операторов коридора:

1. **Непредсказуемость Каспия** — погодный предиктор остановки портов
   (Актау, Курык, Алят + Поти, Батуми, Констанца): пороги по устойчивому ветру
   и порывам, алерты `watch`/`warning`/`critical` с антиспамом и «отбоем».
2. **Отсутствие единого статуса** — `/status`: погодные алерты, позиции судов
   (честное «нет данных» при слабом покрытии AIS), свежие ручные сводки.
3. **Непрозрачность** — новостная лента коридора и данные от доверенных
   источников (очереди, ставки, простои на границах) в одном канале.

## Возможности

| Кому | Что |
|------|-----|
| Все | `/start`, `/help`, `/status`, `/status aktau` (по коду или названию порта) |
| Доверенные источники | `/report` — очередь ⚓️ / ставка 💰 / простой на границе 🚧 / заметка 📝; `/cancel` |
| Админы | `/poll_weather`, `/poll_news` — прогон погоды/новостей «по кнопке»; `/pending`, `/approve <id>`, `/reject <id>` — модерация; `/add_source <tg_id> <role> <имя>` — whitelist |

Публикации в канал: погодные алерты и отбои, новости (дедуп + троттлинг),
одобренные ручные сводки.

## Архитектура

```
Погода (Open-Meteo) ──▶ ┌────────────────────────┐
AIS (AISstream WS)  ──▶ │   services (ядро)      │ ──▶ PostgreSQL
Новости (RSS)       ──▶ │ predictor · tracker    │
Ручной ввод (бот)   ──▶ │ news · reports · status│
                        └──────────┬─────────────┘
                 ┌─────────────────┼──────────────────┬──────────────────┐
                 ▼                 ▼                  ▼                  ▼
          Telegram-бот      Публичный канал     FastAPI (:8000)     Веб-карта (web/)
          (aiogram 3)       (publisher)         /health · /api/v1   React + MapLibre
```

Слои: `integrations/` (внешние API за Protocol-интерфейсами) → `services/`
(бизнес-логика, не знает про Telegram/HTTP) → `bot/`·`api/` (транспорт) →
`db/` (модели + репозитории). Подробнее для разработки — [CLAUDE.md](CLAUDE.md).

## Локальный запуск

Нужны: Python 3.11+, Docker.

```powershell
# 1. Postgres (порт 5433 — 5432 часто занят системным Postgres)
docker compose up -d db

# 2. Окружение
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -e ".[dev]"

# 3. Конфигурация
copy .env.example .env            # заполнить BOT_TOKEN, CHANNEL_ID, ADMIN_USER_IDS

# 4. Миграции (создают схему и сиды портов/судов)
alembic upgrade head

# 5. Запуск: API :8000 + бот + AIS-воркер
python -m app.main
```

Проверка: `GET http://localhost:8000/health` →
`{"status":"ok","db":true,"ais_last_message_age_s":...}`.

Джобы можно гонять и из терминала: `python -m app.scheduler.jobs weather|news`.

## Конфигурация (ENV)

Все параметры — через переменные окружения (`.env` локально, см.
[.env.example](.env.example)). Ключевые:

| Переменная | Значение |
|-----------|----------|
| `BOT_TOKEN`, `CHANNEL_ID`, `ADMIN_USER_IDS` | Telegram: бот, канал (бота — админом!), админы через запятую |
| `DATABASE_URL` | `postgresql+asyncpg://...` |
| `WEATHER_*_WIND/GUST` | пороги предиктора, м/с — **стартовые, калибровать по фактическим остановкам** |
| `AUTO_PUBLISH_REPORTS` | `false` = ручные сводки через модерацию `/approve` |
| `SCHEDULER_ENABLED` | `false` = погода/новости по командам админа; `true` = автопилот по интервалам |
| `NEWS_SOURCES` | RSS/Atom-ленты через запятую |
| `AISSTREAM_API_KEY`, `AIS_BBOX_*` | AIS-стрим и bounding box'ы |
| `VESSELAPI_WEBHOOK_SECRET` | пусто = вебхук `/webhooks/vesselapi` выключен |
| `MOCK_DATA`, `MOCK_TIME_SCALE` | `true` = JSON-API карты отдаёт синтетику без БД; ускорение мок-времени для демо |
| `WEB_DIST_DIR` | собранный фронт (`web/dist`); нет каталога = раздача выключена |
| `CORS_ORIGINS` | origin'ы фронта на другом домене (Vercel) через запятую; пусто = CORS выключен |

## Тесты и линт

```powershell
pytest            # 100+ тестов: предиктор, дедуп, whitelist, AIS, агрегатор, трекинг, карта
ruff check .
black --check .
```

Юнит-тесты гоняются на in-memory SQLite и моках внешних API — сеть не нужна.

Фронт (`web/`):

```powershell
cd web
npm run lint        # Biome: линт + формат одним инструментом (npm run format — починить)
npm run typecheck   # tsc для приложения и e2e
npm test            # Vitest: чистая логика (форматирование, трек, интерполятор, шторка, replay-часы)
npm run build       # tsc + vite build → web/dist
npm run e2e         # Playwright против собранного фронта; API с MOCK_DATA поднимается сам
```

E2E ходит на `http://127.0.0.1:8000`: если API уже запущен — переиспользует его,
иначе стартует `python -m app.main` с `MOCK_DATA=true` (`web/playwright.config.ts`).
Нужен `npm run build` перед запуском и установленный Chromium
(`npx playwright install chromium`; свой бинарник — `PLAYWRIGHT_CHROMIUM_PATH`).
Сценарии: первый экран и поток, плавное движение, карточка и слежение, шкала
времени, смена подложки и 3D, ветер частицами, ссылка на груз и момент времени,
переключение RU/EN, шторка на мобильном, 404/503 от API, браузер без WebGL 2.
Браузер в тестах — с локалью `ru-RU` (язык интерфейса по умолчанию берётся из
браузера). Тесты берут `test` из `web/e2e/fixtures.ts`: на падении в лог
печатаются ошибки консоли, состояние карты и след вызовов камеры — в CI это
единственное, что видно без скачивания артефактов. CI (`.github/workflows/ci.yml`) гоняет всё это на каждый PR; отчёт
Playwright прикладывается артефактом при падении.

## Веб-карта (фаза 2, прототип)

Большая карта коридора с зумом: узлы с погодой и алертами предиктора, паромы
Каспия по AIS, отправки с проекцией положения, слой ветра, сбоку — грузы,
порты и новости. Фронт — `web/` (React 19 + Vite 8 + TypeScript 7 +
MapLibre GL 6), бэкенд — JSON-API `GET /api/v1/snapshot`, `/api/v1/wind`,
`/api/v1/shipments/{ref}` и SSE-поток `/api/v1/stream`
(`app/api/routes/v1.py`, модели — `app/services/map_snapshot.py`).

**Живая карта.** Снимок приходит по SSE каждые `STREAM_INTERVAL_S` секунд
(на Vercel serverless потока нет — фронт сам переходит на поллинг раз в
`POLL_INTERVAL_S`); между снимками грузы и паромы доезжают до новых координат
плавно, паромы поворачиваются по курсу. Кнопка «следить» в карточке держит
груз в центре, любой жест по карте снимает слежение. Переключатель «3D» —
объёмный рельеф и наклон камеры (вращение правой кнопкой или компасом).

**Шкала времени.** Внизу карты — replay за `REPLAY_PAST_HOURS` назад и
`REPLAY_FUTURE_HOURS` вперёд (по умолчанию 72/24): скраб, воспроизведение
×60/×600/×3600, пробел — пауза, LIVE — назад к живым данным. Все ручки API
принимают `at=` (ISO-время) — снимок, ветер, карточка отправки считаются на
этот момент; в моке это чистая функция времени, на боевых данных потребует
индекса по времени. «Сейчас» фронт считает по серверным часам (`server_time`
снимка плюс прошедшее у клиента с учётом `live.time_scale`), а не по своим.

**Ветер частицами.** Слой «Ветер» рисует поле не стрелками, а живыми
частицами — собственный WebGL-слой поверх MapLibre 6
(`web/src/map/windParticles.ts`, по мотивам webgl-wind): положения частиц
живут в текстурах, след — затухающий экранный буфер, проекция — через
`projectTile` из прелюдии MapLibre, так что частицы держатся на месте при
любом зуме, наклоне и на глобусе. Если устройство не тянет (средний кадр
дольше 55 мс три секунды подряд), слой сам переключается на стрелки;
режим можно выбрать в панели карты, выбор запоминается.

**Графики и прогноз.** В карточке порта — спарклайн ветра на 48 часов с
зонами порогов предиктора (watch/warning/critical) и оценкой «когда
закроется / когда откроется»; в карточке груза — отклонение от плана по
чекпоинтам (факт минус расписание, будущие узлы — по текущей задержке) и
прогноз прибытия. В шапке — сводка за 7 суток: переходы через Каспий,
средняя задержка, простой портов (`summary` в снимке). Графики — свой SVG
без библиотек (`web/src/components/charts/`), расчёты — чистый
`web/src/forecast.ts`.

**Поиск, фильтры, ссылки.** Список грузов ищется по номеру, клиенту, грузу и
пунктам отправления/назначения и фильтруется по состоянию (активные / в пути /
стоянка / с задержкой / доставлены) и плечу (Китай — Казахстан, Каспий,
Кавказ, Чёрное море, Европа).
Состояние карты живёт в адресе: `?s=MC-2024-0042&view=5.5/43.6/51.2&basemap=
satellite&at=2024-09-05T12:00Z` — ссылку можно отправить, откроется тот же
груз на том же виде и в тот же момент replay; кнопка «поделиться» — Web Share
API на телефоне, буфер обмена на десктопе. Заголовок вкладки повторяет
выбранный груз.

**Русский и английский.** Переключатель RU/EN в шапке; словари —
`web/src/i18n/ru.ts` (источник ключей) и `en.ts` (покрытие проверяется
тестом). Бэкенд отдаёт вместе с русскими строками для бота коды (`last_event_kind`,
`hold_code`, `phase_code`, `port_code`) и английские названия узлов (`name_en`),
а фронт собирает подписи сам (`web/src/i18n/labels.ts`) — так один API
кормит и бота, и карту на любом языке. Выбор запоминается, по умолчанию —
язык браузера.

**Требования и устойчивость.** MapLibre 6 рисует только через WebGL 2 — без
него на месте карты понятный экран, а панель с грузами, портами и новостями
работает. Карта, панель управления и боковая панель обёрнуты в отдельные
ErrorBoundary: падение одной части не гасит остальные. Карта грузится
отдельным чанком — первый экран (81 КБ gzip) появляется до MapLibre.

**Честная модель положения груза.** Сплошного GPS/AIS в коридоре нет
(Каспий почти слеп, у железных дорог нет публичного трекинга), поэтому
положение отправки — это последнее *подтверждённое* событие (отправление /
прибытие в узле, AIS-позиция парома) плюс *проекция* по расписанию между
чекпоинтами (`app/services/tracking.py`). На карте подтверждённая точка —
сплошная, проекция — пунктир с пульсом; в карточке видно, что это оценка.

**Мок-режим.** `MOCK_DATA=true` — API отдаёт синтетику без БД и внешних
сервисов (`app/integrations/mock/`): паромы ходят по циклу Курык/Актау ↔ Алят
(два намеренно «вне AIS»), ~10 отправок в разных состояниях (на пароме, ждёт
погоды в Актау, на рельсах в степи, на таможне AZ/GE, доставлен…), поле ветра
с циклоном над северным Каспием — уровни портов считаются боевыми порогами
предиктора. Всё детерминировано по времени и движется. `MOCK_TIME_SCALE=60`
ускоряет мок-время (час за минуту) для демо.

```powershell
# бэкенд в мок-режиме (без Postgres)
$env:MOCK_DATA='true'; .venv\Scripts\python -m app.main      # API + фронт на :8000

# фронт в dev-режиме с hot reload (проксирует /api на :8000)
cd web; npm install; npm run dev                              # http://localhost:5173

# сборка: web/dist раздаёт FastAPI по адресу /
cd web; npm run build
```

Без `MOCK_DATA` API работает на боевых источниках: порты/суда/сводки — из
агрегатора статуса и БД, новости — из `news_items`; отправки и поле ветра
пока без источника (фронт показывает «нет данных»).

**PWA и превью ссылок.** Манифест, иконки и сервис-воркер (`vite-plugin-pwa`):
приложение ставится на экран телефона, оболочка открывается офлайн, последний
снимок отдаётся из кэша с пометкой «офлайн · данные на …» в топбаре. Для
превью ссылки в Telegram/WhatsApp задайте публичный адрес при сборке —
`VITE_PUBLIC_URL=https://mc-status.example` (на Vercel берётся из
`VERCEL_PROJECT_PRODUCTION_URL` автоматически): тогда `og:image` станет
абсолютным и покажется картинка `web/public/og.png`.

**Подложки.** Переключатель на карте: «Тёмная» (векторная, VersaTiles /
OpenFreeMap, без ключа), «Светлая» (Positron), «Детальная» (Liberty),
«Спутник» (снимки Esri + подписи). Если векторный хост не отвечает, фронт
сам откатывается на растровые тайлы CARTO и показывает подсказку — карта
не остаётся пустой. Плюс 3D-глобус (проекция MapLibre) и рельеф (hillshade
по AWS Terrain Tiles). Выбор запоминается в браузере.

Свой стиль (MapTiler «Dataviz Dark», Stadia, самохост Protomaps) — любой
MapLibre style.json через переменную сборки: `web/.env` →
`VITE_MAP_STYLE=https://api.maptiler.com/maps/dataviz-dark/style.json?key=…`.
Google Maps намеренно не подключён: тайлы Google нельзя рисовать чужим
рендерером без Map Tiles API с сессионными токенами и биллингом, а их JS-SDK
потребовал бы переписать все слои; при необходимости добавляется отдельным
пресетом.

## Деплой на Vercel

Vercel — это статика + serverless-функции, а не постоянный процесс: бот
(long polling), AIS-стрим по WebSocket и планировщик там жить не могут.
Поэтому два варианта.

**A. Демо целиком на Vercel (мок-данные).** Фронт раздаётся CDN, а
`/api/v1/*` и `/health` — Python-функция [api/index.py](api/index.py) с тем
же FastAPI (маршрутизацию задаёт [vercel.json](vercel.json)).

1. vercel.com → Add New → Project → импортировать репозиторий. Root Directory
   оставить корнем репо, Framework Preset — Other (команды сборки уже в
   `vercel.json`).
2. Environment Variables: `MOCK_DATA=true`. Больше ничего не нужно —
   ни БД, ни ключей.
3. Deploy. Проверка: `https://<проект>.vercel.app/health` →
   `{"status":"ok","db":false,...}`, карта — на корне.

Если сборка падает на `cd: web: No such file or directory` — в Project
Settings → General → Root Directory стоит `web`: для варианта A поле
должно быть пустым (корень репо), затем Redeploy. Команды в `vercel.json`
переживают оба значения, но Python-функция и `/api` есть только из корня.

Если фронт открылся, а `/api/v1/snapshot` отвечает 503/500 — открой
`/health`: `"mock": false` значит, что `MOCK_DATA` не `true` (Vercel при
импорте подтягивает `MOCK_DATA=false` из `.env.example`). Поправь переменную
для Production и сделай Redeploy: изменения переменных вступают в силу
только с новым деплоем.

Зависимости Python ставятся из [requirements.txt](requirements.txt)
(зеркало `pyproject.toml`, тест следит, чтобы не разъехались). Если указать
`DATABASE_URL` (Neon/Supabase, лучше pooler-адрес) и убрать `MOCK_DATA`,
функция отдаст боевые порты/суда/новости из БД — но наполнять её будет
некому без второго варианта.

**B. Продакшен: фронт на Vercel, бэкенд на Railway.** Бот, AIS, погода и
новости крутятся на Railway (ниже), Vercel раздаёт только `web/`.

1. Vercel → Add New → Project, тот же репозиторий, **Root Directory = `web`**,
   Framework Preset — Vite (в `web/vercel.json` уже задан).
2. Environment Variables: `VITE_API_BASE=https://<сервис>.up.railway.app`
   (без завершающего слэша) — фронт ходит в API напрямую.
3. На Railway добавить `CORS_ORIGINS=https://<проект>.vercel.app` (через
   запятую можно и preview-домены) — иначе браузер заблокирует запросы.

В обоих вариантах вся конфигурация карты (подложки, `VITE_MAP_STYLE`)
задаётся переменными сборки Vercel.

## Деплой (Railway)

1. Подключить GitHub-репозиторий, Railway соберёт по [Dockerfile](Dockerfile)
   (конфиг — [railway.json](railway.json); первая стадия собирает `web/`,
   миграции применяются на старте).
2. Добавить Postgres-плагин; проставить `DATABASE_URL`
   (заменить `postgresql://` на `postgresql+asyncpg://`).
3. Прописать ENV из [.env.example](.env.example).
4. Healthcheck — `/health`.

Один сервис = один процесс (API + бот + AIS). Второй инстанс бота запускать
нельзя (конфликт polling).

## Известные ограничения

- **AIS на Каспии почти слеп** (мало береговых приёмников — проверено вживую):
  статус судна без свежей позиции — «нет данных», а не «стоит». MMSI паромов
  ASCO в сидах пустые — заполняются руками по мере появления судов в эфире.
- **Пороги ветра не откалиброваны** — стартовые значения из спеки; уточнять
  по фактическим остановкам портов (в этом ядро ценности продукта).
- **middlecorridor.com без RSS** — официальный портал потребует
  скрейпер-реализацию `NewsProvider` (интерфейс готов).
- **VesselAPI-клиент не сверен** с боевой документацией тарифа — использовать
  после проверки формата ответов.
