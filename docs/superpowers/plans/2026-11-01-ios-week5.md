# iOS, неделя 5 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Точность прогноза (синтетика с пометкой), ETA с вилкой и разбором задержки, карта «как в Telegram» (полноэкранная из карточки, закреплённая живая на «Коридоре»).

**Architecture:** Бэкенд: `services/delay_breakdown.py` (чистые функции) + поля `Shipment.eta_latest`, `delay_breakdown`; ETA в очереди — от прогноза очереди; `MockAccuracySource` — синтетические шторма → тот же `score_events`; `/api/v1/accuracy` отдаёт его в моке с `demo: true`. iOS: модели и подписи в MCCore (`swift test`), экраны — MapKit/SwiftUI.

**Tech Stack:** Python 3.11/FastAPI/pydantic/pytest; Swift 6, SwiftUI, MapKit, XCTest/XCUITest.

**Spec:** `docs/superpowers/specs/2026-11-01-ios-week5-design.md`; правила — `CLAUDE.md`.

## Global Constraints

- Всё из недель 2–4: iOS 17, Swift 6 strict, MCCore без UI-фреймворков, новые поля API — необязательные в iOS, строки RU/EN из кодов, цвета — `Theme`, `DEMO_CONTROL` только локально.
- Сумма `delay_breakdown` = `delay_hours` (± 0,1 ч на округлении).
- `eta_latest ≥ eta`; доставлен — равны.
- Мок-точность детерминирована, не зависит от перевода часов демо; в ответе `demo: true`.
- Карта в прокручиваемом списке — без жестов; жесты — только в полноэкранной и в закреплённой карте «Коридора».
- Команды iOS — с `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`, симулятор `iPhone 17`.

## Review Focus

1. Груз в пути без очереди и без причин — разбор из одной части `schedule` либо пуст при задержке < 1 ч → тест в Task 1.
2. История 0398 на каждом такте: сумма разбора = задержке, `eta ≤ eta_latest`, после отхода — фактическое прибытие ≤ `eta_latest`, показанной в шторм → тест в Task 1.
3. Порт без штормов в синтетике — `pod`/`far` = None, итог по коридору не делится на ноль → тест в Task 2.
4. Старый бэкенд без `eta_latest`/`delay_breakdown`/`vessels` — приложение показывает одну дату и прячет секции → тест в Task 3.
5. Паром без живой позиции на карте «Коридора» не рисуется («нет данных», не «стоит») → тест в Task 3 (фильтр в MCCore).

### Task 1: Разбор задержки и вилка ETA (бэкенд)

**Files:** Create `app/services/delay_breakdown.py`; Modify `app/services/tracking.py` (`ShipmentPlan.delay_causes`, `Shipment.eta_latest`, `Shipment.delay_breakdown`, ETA в очереди), `app/integrations/mock/story.py` (интервалы причин 0398); Test `tests/test_tracking.py`, `tests/test_demo.py`.

**Interfaces — Produces:**
- `@dataclass(frozen=True, slots=True) class DelayCause: code: str; node_code: str | None; start: datetime; end: datetime`
- `class DelayPart(BaseModel): code: str; node_code: str | None = None; hours: float`
- `def breakdown(causes: Sequence[DelayCause], since: datetime, now: datetime, delay_hours: float, fallback: DelayPart | None) -> list[DelayPart]` — часы причины = пересечение `[start, end)` с `[since, now]`; части с ≥ 0,1 ч; остаток `delay − сумма` ≥ 1 ч → `schedule`; сумма > задержки → части масштабируются; без причин — `fallback` с `hours = delay`; задержка < 1 ч → `[]`; сортировка по убыванию часов; часы округлены до 0,1.
- `HOLD_TO_CAUSE = {"weather_ban": "weather_ban", "ferry_loading_wait": "ferry_wait", "ferry_return_wait": "ferry_wait", "customs_wait": "customs_wait"}`
- `project_shipment`: `since` = плановый отход из текущего узла ожидания или плановое прибытие текущего плеча (как сейчас считается задержка); ETA в очереди: `eta = now + p50 + путь`, `eta_latest = now + p90 + путь`, путь = `legs[-1].arrive_at − leg_from(queue.port_code).depart_at`; иначе `eta_latest = eta + clamp(10 % оставшегося пути, 6, 72) ч`; доставлен — `eta_latest = eta`.
- История 0398: `ferry_wait [T0−18, T0+6)`, `weather_ban [T0+6, T0+66)`, `ferry_wait [T0+66, T0+70)` (узел AKTAU).
